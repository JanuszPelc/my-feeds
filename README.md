<a name="story-27487"><img src="https://wsrv.nl/?url=https%3A%2F%2Fimg.piri.net%2Fresim%2Fupload%2F2018%2F06%2F27%2F12%2F22%2F71d5abbc9.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>An analysis of nearly 70,000 black rhino sightings across 14 reserves reveals that while the species is predominantly solitary and prone to aggression, individuals regularly form peaceful groups with familiar associates. The study found that about 8% of sightings involved groups of three to seven animals, and these interactions typically occurred between rhinos that had previously associated with one another.</p><p>These findings provide critical insights for conservation translocations, where moving animals to new areas can trigger lethal fighting. Researchers suggest that selecting rhinos with existing social bonds and carefully managing the ratio of adult males—which are more frequently avoided by other adults and associated with lower survival rates—can significantly reduce post-release aggression and improve population recovery efforts.</p>

<h2><img src="images/computer-programming.png" width="28" align="texttop" /> &nbsp;Phil Eaton Surveys Memory Management in 40 Major C Projects</h2>
<a name="story-27563"><img src="https://wsrv.nl/?url=https%3A%2F%2Fimage.slidesharecdn.com%2Fdynamicmemoryallocation-240708091439-6ca10933%2F75%2FDynamic-Memory-Allocation-in-C-programming-4-2048.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Phil Eaton surveyed 40 major C software projects to examine how they handle memory allocation, finding that only eight projects rely exclusively on manual malloc and free operations. The analysis reveals that while manual memory management remains widespread, many prominent codebases incorporate higher-level primitives such as memory regions, reference counting, garbage collection, and scope-based cleanup compiler extensions.</p><p>Memory strategies vary significantly across infrastructure projects, with some prioritizing strict manual control while others lean heavily on specialized allocators. For example, SQLite relies entirely on manual allocation for correctness, whereas projects like Linux and QEMU have increasingly adopted compiler extensions for automated scope cleanup, and others utilize region-based or garbage-collected allocation models.</p>

<h2><img src="images/computer-security.png" width="28" align="texttop" /> &nbsp;Microsoft FORGE Lab Identifies Memory Safety Issues in Rust Standard Library</h2>
<a name="story-27179"><img src="https://wsrv.nl/?url=https%3A%2F%2Fforge-blog.github.io%2Fposts%2Frust-std-memory-safety%2Fpanic-safety.svg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Researchers at Microsoft's FORGE Lab have uncovered multiple memory safety vulnerabilities within Rust's core and standard libraries, demonstrating how code written entirely in safe Rust can occasionally trigger undefined behavior. Utilizing an AI-powered vulnerability scanner, the investigation revealed three recurring patterns of misplaced trust in unsafe code: trusting code not to panic, assuming user-provided implementations are correct, and relying blindly on underlying system behaviors.</p><p>These findings illustrate the inherent difficulties of maintaining soundness in unsafe blocks that underpin safe APIs across widely used programming languages. As Rust becomes increasingly integrated into critical infrastructure, identifying and addressing these edge cases in foundational libraries remains vital for maintaining overall software security.</p>
