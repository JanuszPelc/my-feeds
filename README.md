<h2><img src="images/computer-programming.png" width="28" align="texttop" /> &nbsp;Dennis Forbes Analyzes SQLite Performance Slowdown Caused by Zig Libc Rewrite</h2>
<a name="story-26451"><img src="https://wsrv.nl/?url=https%3A%2F%2Fmintcdn.com%2Fcodspeed%2FBdvfbpKO_S3Ha4vy%2Fguides%2Fbenchmarking-a-go-gin-api%2Fassets%2Fsqlite-regression-ui.png%3Ffit%3Dmax%26auto%3Dformat%26n%3DBdvfbpKO_S3Ha4vy%26q%3D85%26s%3Da9b94424ad0f97ff4b17a541f14a5bd8&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Developer Dennis Forbes encountered a severe performance regression when inserting large JSON datasets into SQLite via a Rust service, with operations taking minutes instead of milliseconds. The bottleneck was traced to CPU-bound string tokenization during cross-platform compilation using Zig's `cc` compiler.</p><p>The slowdown originated from a pure-Zig replacement of standard C library string functions like `strspn` within Zig's libc implementation. Unlike standard library versions, the rewritten function repeatedly measures the entire length of the string on each iteration, creating a quadratic complexity trap that dramatically degrades tokenization performance on large files.</p>
<p>Nov 6 · <a href="https://dennisforbes.ca/blog/microblog/2026/10/the_accidental_12000x_sqlite_slowdown/">dennisforbes.ca</a> | <a href="https://lobste.rs/s/lh1j0e/shlemiel_painter_is_back_how_zig_s_libc">lobsters</a> | <a href="https://news.ycombinator.com/item?id=50247203">hacker news</a></p>

<h2><img src="images/computer-programming.png" width="28" align="texttop" /> &nbsp;The Origins and Early Development of BSD Unix</h2>
<a name="story-26194"><img src="https://wsrv.nl/?url=https%3A%2F%2Fimage4.slideserve.com%2F9082739%2Fthe-bsd-unix-l.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>In the late 1970s, Bill Joy and researchers at UC Berkeley created the Berkeley Software Distribution (BSD) by bundling a Pascal compiler, line editors, and other utilities as an add-on package for AT&amp;T Unix. By distributing these tools at cost, Berkeley fostered a tradition of sharing that helped spread Unix throughout universities and research institutions.</p><p>Following the release of the expanded 2BSD distribution, the acquisition of a VAX computer at Berkeley led graduate student Ozalp Babaoglu and Bill Joy to add virtual memory support to Unix 32/V. Their work culminated in 3BSD in December 1979, drawing the interest of DARPA and laying the groundwork for Unix's widespread adoption in government-funded research.</p>

<h2><img src="images/computer-security.png" width="28" align="texttop" /> &nbsp;OpenSSH on musl-based Linux Distributions Vulnerable to Password Bypass</h2>
<a name="story-26524"><img src="https://wsrv.nl/?url=https%3A%2F%2Fi.ytimg.com%2Fvi%2Fe-ZwtnhSyFE%2Fmaxresdefault.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>OpenSSH installations running on musl libc—including Alpine, OpenWrt, and Buildroot—are vulnerable to a password bypass affecting accounts with no password (marked with '*' in /etc/shadow). When a password longer than 256 characters is provided, musl's crypt() function returns '*' due to a length limit in its SHA512 implementation, which OpenSSH incorrectly validates as a successful match.</p><p>The vulnerability specifically affects systems using musl that do not utilize PAM and have password authentication enabled. To mitigate this risk, users are advised to upgrade to OpenSSH 10.6p2 or disable password authentication in their SSH configuration.</p>
<p>Nov 5 · <a href="https://sshhole.com">sshhole.com</a> | <a href="https://news.ycombinator.com/item?id=50378228">hacker news</a></p>
