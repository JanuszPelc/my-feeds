<h2><img src="images/computer-programming.png" width="28" align="texttop" /> &nbsp;Examining Nondeterminism in the Futhark Programming Language</h2>
<a name="story-26828"><img src="https://wsrv.nl/?url=https%3A%2F%2Fimage.slidesharecdn.com%2F1216jmicro01-221124044524-d404c711%2F85%2FDESIGN-OF-DOUBLE-PRECISION-FLOATING-POINT-MULTIPLICATION-ALGORITHM-WITH-VECTOR-SUPPORT-2-638.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>The Futhark programming language blog examines the origins of nondeterminism within its parallel execution model, identifying two primary sources: language abuse through unsafe constructs like unchecked scatter operations, and floating-point roundoff errors caused by non-associative operations. While Futhark is generally characterized as a deterministic language, parallel reductions and scans alter the order of floating-point additions depending on hardware schedules, leading to replayable or approximate results.</p><p>Although fully deterministic implementations—such as tree-based summation—are possible, they incur significant performance penalties compared to hardware-optimized routines that rely on atomic instructions or backend-specific chunking. The post highlights that sacrificing strict determinism is a deliberate design choice required to maintain high performance on modern parallel hardware, balancing numerical consistency against execution speed.</p>
<p>Nov 9 · <a href="https://futhark-lang.org/blog/2026-11-04-nondeterminism.html">futhark-lang.org</a> | <a href="https://lobste.rs/s/4lgvnf/nondeterminism_futhark">lobsters</a></p>

<h2><img src="images/computer-programming.png" width="28" align="texttop" /> &nbsp;Analysis of Deno Security Model and Permission System Limitations</h2>
<a name="story-26818"><img src="https://wsrv.nl/?url=https%3A%2F%2Fai.devtheworld.jp%2Fposts%2Fdeno-ai-modules-secure-runtime%2Fdeno-permission-model.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>An essay by developer Goldstein critiques the Deno JavaScript runtime's security model, arguing that its built-in permission system is fundamentally flawed and provides a false sense of security. The piece details how Deno's approach emulates operating system security controls at the standard library level rather than properly sandboxing the underlying process.</p><p>The analysis highlights specific attack vectors, including terminal prompt manipulation via in-band data streams and bypasses of granular execution permissions like `--allow-run` through environment variables such as `PATH` and `LD_PRELOAD`. Because most system binaries and editors are highly configurable, relying on partial runtime restrictions is insufficient, leading the author to recommend traditional OS-level sandboxing tools like bubblewrap instead of Deno's runtime permissions.</p>

<p>Researchers at the University of Würzburg have successfully synthesized and isolated oxoboranes, a class of reactive molecules featuring a triple bond between boron and oxygen that had eluded chemists for over 60 years. The approach successfully yielded three distinct oxoboranes with computational support from Tezpur University researchers, pointing toward potential new pathways for synthesizing other elusive chemical compounds across the periodic table.</p>

## Worth knowing

The feeds are aggregated by an agentic pipeline, which rewrites every title and summary in
a plain, measured tone. Lead images are chosen by vision models. Nothing is reviewed by
hand, so check anything that matters against the linked sources.

Feed links rarely change, but if a feed in your reader goes quiet for a few days, come back
here and resubscribe.
