<p>Molly, a security-focused fork of the Signal messaging application for Android, has not received a software update since late July 2026. <h2>Parameter Researchers Disclose ChatGPT Share Link Vulnerability Enabling Account Takeover</h2>
<a name="story-26054"><img src="https://wsrv.nl/?url=https%3A%2F%2Fimgv2-2-f.scribdassets.com%2Fimg%2Fdocument%2F702136017%2Foriginal%2Fa971f62113%2F1%3Fv%3D1&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Researchers at Parameter disclosed a security vulnerability in ChatGPT's web application that allowed a maliciously crafted public share link to execute arbitrary JavaScript within a victim's signed-in session. By combining an interactive graph feature, MathLive message handling flaws, and a Content Security Policy bypass involving YouTube, an attacker could traverse the preview sandbox and access authenticated frontend APIs. This enabled the retrieval of private conversation histories and complete account compromise simply by having a user open a shared link.</p><p>OpenAI classified the issue as a P1 bug and rolled out fixes across ChatGPT's web frontends, fully resolving the vulnerability by October 26, 2026. The vulnerability highlights the risks that emerge when multiple independent features—such as sandboxed previews, cross-frame messaging, and math layout libraries—interact unexpectedly. The incident underscores the importance of strict origin validation, secure message handling, and robust sandboxing for dynamically created documents.</p>

<h2>Mozilla Details Strategy to Defend Firefox Against Automated Patch-Gapping</h2>
<a name="story-26047"><img src="https://wsrv.nl/?url=https%3A%2F%2Fblog.mozilla.org%2Fwp-content%2Fblogs.dir%2F278%2Ffiles%2F2026%2F10%2Fpatch-gap-simple-pill-1024x253.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Mozilla is adapting Firefox's security practices to counter patch-gapping, a vulnerability exploitation method accelerated by AI models that can rapidly reverse-engineer software security fixes. While frontier models have enabled the Firefox team to significantly increase its security fix rate, malicious actors are increasingly using automated tools to target the brief window of time between a code fix and full user deployment.</p><p>To neutralize this threat regardless of attack speed, Firefox is introducing a structural defense that staggers fixes across independent sandbox layers so that interdependent vulnerabilities do not share overlapping patch gaps. Additionally, the browser team is accelerating its release cycle, withholding regression tests until fixes are shipped, and scanning new code commits to maintain a security advantage over automated attackers.</p>

<h2>Yarr RSS Reader Vulnerable to Cross-Site Scripting via Iframe Sanitization Bypass</h2>
<a name="story-26037"><img src="https://wsrv.nl/?url=https%3A%2F%2Fbear-images.sfo2.cdn.digitaloceanspaces.com%2F0x67673068%2Fimage-1.webp&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Security researcher Matthew Hogg has detailed a cross-site scripting (XSS) vulnerability in the open-source Go-based RSS reader yarr. The flaw stems from a parsing discrepancy between Go's net/url package and browser-based JavaScript URI handling when sanitizing iframe sources.</p><p>By crafting an iframe source that exploits URL parsing differences, an attacker can bypass domain whitelist checks and execute arbitrary JavaScript code when a user loads a malicious RSS post. Although yarr functions primarily as a self-hosted local application, the vulnerability could permit malicious payloads to inspect or track other feeds read by the user through DOM manipulation.</p>

<h2>Go 1.28 HTTP/2 Parking Mechanism Reduces Server Memory Usage</h2>
<a name="story-26028"><img src="https://wsrv.nl/?url=https%3A%2F%2Fabdolirad.me%2Farticles%2Fgo-1-28-http2-parking-memory%2F01-rss-scaling.svg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>An analysis of the draft Go 1.28 release notes examines a new HTTP/2 server mechanism called parking, which allows connection-serving goroutines to exit when there is no active work instead of waiting idle. Benchmarks comparing a Go 1.28 development build with parking enabled versus disabled show that handling 5,000 idle HTTP/2 connections results in 5,000 fewer active goroutines and a resident set size (RSS) reduction of roughly 85 to 93 MiB.</p><p>The benchmark results indicate that enabling parking lowers stack memory usage by approximately 78 MiB under the same load, while heap allocation metrics remain variable across test runs. Because the feature is evaluated on a pre-release development build using an experimental and temporary debug setting, the findings highlight potential memory efficiency gains for servers maintaining thousands of idle connections rather than guaranteed outcomes for all workloads.</p>
<p><small>Links: <a href="https://abdolirad.me/articles/go-1-28-http2-parking-memory/">abdolirad.me</a> | <a href="https://lobste.rs/s/mhmqky/go_1_28_s_http_2_parking_measuring_memory">discussion</a> | <a href="https://news.ycombinator.com/item?id=50251893">hacker news</a></small></p>

<h2>Go Security Team Advises on Mitigating CVE-2026-98432 Linux Kernel Flaw</h2>
<a name="story-26027"><img src="https://wsrv.nl/?url=https%3A%2F%2Fnews-pravda.com%2Fimg%2F20261031%2F82035a6900331972800bc4ed99426020.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>The Go Security Team has issued guidance regarding CVE-2026-98432, a critical use-after-free vulnerability affecting IPv4 TCP connection handling in the Linux kernel that can allow remote code execution when Multipath TCP listeners are exposed. While upgrading to a patched kernel remains the definitive fix, Go 1.24 and later versions enable Multipath TCP by default for listen sockets on Linux, making programs potentially susceptible unless mitigated.</p><p>Developers can disable Multipath TCP globally at runtime using the "GODEBUG=multipathtcp=0" environment variable, at build time by adding "godebug multipathtcp=0" to a go.mod file, or explicitly per socket using Dialer and ListenConfig settings. However, the security team cautions that program-by-program mitigations are fragile and stresses that updating the kernel is the only complete remedy, noting that any future changes to Go's default behavior will be discussed publicly.</p>
<p><small>Links: <a href="https://groups.google.com/g/golang-announce/c/PCoQcdxoScw">groups.google.com</a> | <a href="https://lobste.rs/s/mp8yqt/protecting_against_cve_2026_98432">discussion</a> | <a href="https://news.ycombinator.com/item?id=50298526">hacker news</a></small></p>
