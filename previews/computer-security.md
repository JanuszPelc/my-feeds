<a name="story-28338"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwww.shuizilong.com%2Fhouse%2Fwp-content%2Fuploads%2F2023%2F04%2Fself-debugging.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Wolverine is a tool designed to give Python scripts self-healing capabilities by utilizing GPT-4 to diagnose and repair runtime errors. The system automatically captures error messages from crashing scripts, sends them to the LLM for a solution, and applies the suggested code changes to continue execution automatically.</p><p>The author highlights a critical security vulnerability where malicious user input can trigger error messages that function as prompt injections. In such cases, GPT-4 might execute unauthorized commands, such as downloading and running remote scripts, effectively weaponizing the self-healing mechanism. The author advises against deploying these tools in production environments due to these risks and the potential for unpredictable code execution.</p>

<h2>GitHub Implements Default Blocks on Dangerous Actions Triggers</h2>
<p>GitHub will start blocking the pull_request_target trigger by default in public repositories on December 2, 2026. This change addresses vulnerabilities where triggers such as pull_request_target and issue_comment allow external actors to execute workflows with access to repository secrets, a vulnerability referred to as a "pwn request." Organizations can manage these risks by implementing event policies to restrict or disable specific triggers across all repositories.</p><p>The Python Software Foundation (PSF) has already applied these security policies to its stewarded organizations to mitigate supply chain compromises similar to those seen in the Ultralytics and LiteLLM incidents. Maintainers are encouraged to use "Evaluate mode" to audit existing workflows before enforcing these policies to ensure that legitimate automated tasks, like labeling pull requests from forks, remain functional.</p>

<h2>Ghostscript CVE-2026-125396 Allows Remote Code Execution via Font Loader</h2>
<a name="story-28254"><img src="https://wsrv.nl/?url=https%3A%2F%2Fuploads.sempreupdate.com.br%2F2026%2F04%2Fn8YDWSbv-copy-fail-linux-cve-2026-31431-acesso-root.webp&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Researchers at pwn.ai have identified a use-after-free vulnerability (CVE-2026-125396) in Ghostscript’s Type 1 font loader. The flaw provides a write-what-where primitive in native memory, allowing an attacker to bypass the -dSAFER sandbox and achieve remote command execution. The exploit is triggered by delivering a specially crafted document to an application that passes the file to the Ghostscript interpreter for rendering.</p><p>The research demonstrates that common image processing tasks—such as cropping images or generating previews in PHP (Imagick), Python (Pillow, imageio), and Qt—can reach the vulnerable interpreter. Even if an application does not call Ghostscript directly, its underlying dependencies may do so when processing PostScript or PDF content disguised as other file types. The vulnerability stems from a failure to check operand types in a font loading helper, which, combined with a memory management error where a global dictionary retains a reference to a reclaimed local object, leads to arbitrary memory corruption.</p>

<h2>Enroute Scales Git Infrastructure to 300,000 Repositories by Replacing Multi-Raft</h2>
<a name="story-28195"><img src="https://wsrv.nl/?url=https%3A%2F%2Fenroute.sh%2Fblog%2Fscaling-horizontally-how-we-moved-beyond-multi-raft%2Farchitecture.svg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Enroute has transitioned its Git infrastructure from a Multi-Raft architecture to a hybrid system using a Raft-based root log and Vertical Paxos-inspired shard logs. This change addresses the performance bottlenecks and operational complexity caused by managing per-repository leader elections and heartbeats as repository counts scale. In the new architecture, the root log manages node membership and appoints sequencers for individual shard logs, which maintain the actual repository state and replication.</p><p>Benchmarking revealed that the new design maintains a 99th percentile push latency of 47 ms across 100,000 repositories, significantly outperforming the previous system. The team validated the new consensus protocol using Stateright for formal model checking and Jepsen for fault injection. Future plans include developing a continuous placement driver for proactive load balancing, implementing root log learners to maintain commit efficiency, and adding point-in-time restoration capabilities.</p>
