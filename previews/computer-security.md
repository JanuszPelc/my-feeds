<h2>Phorion Discovers Persistent SSH Backdoor in Official Claude Code Extension</h2>
<a name="story-25960"><img src="https://wsrv.nl/?url=https%3A%2F%2Fcoinedition.com%2Fwp-content%2Fuploads%2F2026%2F07%2Fmagnific_alibaba-to-ban-claude-cod_74x4rjnJAL.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Phorion identified a supply-chain compromise affecting version 2.1.313 of the official Claude Code for VS Code extension distributed on the Cursor Marketplace. The malicious extension bundle executes an injected script upon loading that installs an attacker-controlled Ed25519 public key into authorized_keys, initiates a persistent reverse SSH tunnel, and transmits host reconnaissance data.</p><p>The cross-platform implant targets macOS, Linux, and Windows systems, though researchers identified several implementation flaws, including a macOS check failure that can disrupt inbound access if Remote Login is disabled. Following the discovery, marketplaces removed the malicious build, prompting recommendations for organizations to audit environments for the affected version and initiate incident response procedures.</p>

<h2>Tech Startups and AI Labs Embrace Formal Verification to Secure Code</h2>
<a name="story-25911"><img src="https://wsrv.nl/?url=https%3A%2F%2Fbillionhopes.ai%2Fwp-content%2Fuploads%2F2026%2F02%2F5-KC-21-Billion-Hopes-Image-5-scaled.jpeg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Tech startups and major AI labs are increasingly turning to formal verification—a mathematical method used to prove code is bug-free—to secure software generated by artificial intelligence. Companies across the tech industry continue to weigh the high costs and potential slowdowns of formal verification against the promise of enhanced reliability and security.</p>

<h2>David Buchanan Demonstrates C2PA Trust Model Vulnerabilities</h2>
<a name="story-25912"><img src="https://wsrv.nl/?url=https%3A%2F%2Fpub.mdpi-res.com%2Fapplsci%2Fapplsci-16-03391%2Farticle_deploy%2Fhtml%2Fimages%2Fapplsci-16-03391-g001.png%3F1775123784&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Security researcher David Buchanan has demonstrated a proof-of-concept showing how the Coalition for Content Provenance and Authenticity (C2PA) trust ecosystem could be compromised in a manner similar to the recent eMudhra certificate authority incident. By generating a signature that chains to Google's C2PA root CA using a leaf certificate with a private key of four, the demonstration highlights potential structural weaknesses in digital media authentication.</p><p>The experiment reveals that current media verification tools largely lack robust revocation-checking mechanisms and struggle with trust models comparable to those that complicated the Web PKI response to the eMudhra compromise. Although the methods used to construct the demonstration are publicly known, the findings emphasize critical vulnerabilities in emerging content provenance standards and the tools designed to enforce them.</p>

<h2>Mark Blaszczyk Details Android SMS of Death Zero-Click Denial-of-Service Vulnerability</h2>
<a name="story-25838"><img src="https://wsrv.nl/?url=https%3A%2F%2Fblog.gridinsoft.com%2Fwp-content%2Fuploads%2F2025%2F01%2Fexploitation-process-samsung-zeroclick.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Security researcher Mark Blaszczyk has detailed a zero-click denial-of-service vulnerability in Android, dubbed "SMS of Death," which can crash the telephony service and drop active calls—including emergency calls—using a single malformed WAP Push message. The flaw stems from an unchecked cast of a WSP header length read as a 64-bit integer into a 32-bit signed integer, triggering a NegativeArraySizeException that terminates the telephony process without any user interaction or notification.</p><p>According to the disclosure, rapid transmission of the payload can corrupt the SQLite database behind SMS storage, causing persistent crash-on-boot loops that require removing the SIM card or using ADB for recovery. Despite being reported to the Android &amp; Google Devices VRP with a suggested one-line patch, Google ultimately classified the issue as a non-security issue and declined to fix it, prompting the researcher to publish a public proof-of-concept.</p>
<p><small>Links: <a href="https://smsofdeath.com/">smsofdeath.com</a> | <a href="https://news.ycombinator.com/item?id=50285452">hacker news</a></small></p>
