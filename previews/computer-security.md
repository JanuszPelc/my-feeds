<h2>Amazon Replaces Claude Sonnet 4.6 with Strands Decider for Internal Ticket Labeling</h2>
<a name="story-27085"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwww.eesel.ai%2F_next%2Fimage%3Furl%3Dhttps%3A%2F%2Fwmeojibgfvjvinftolho.supabase.co%2Fstorage%2Fv1%2Fobject%2Fpublic%2Fpublic_assets%2Fblog-gen%2F8a5ea7e3-c792-48e9-a2ab-b082aa5bb039%26w%3D1680%26q%3D75&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Amazon and AWS engineers replaced Claude Sonnet 4.6 with the Strands Decider E4B decision model to label tickets within an internal system. This transition reduced token costs by approximately 98% and decreased average call latency from 4,215 ms to 897 ms. The model maps various ticket types, such as customer escalations and security findings, into a fixed set of 20 categories.</p><p>The efficiency gains result from the decision model returning a single choice rather than a full JSON object and utilizing significantly shorter prompts. The implementation utilizes AWS services such as SageMaker, SQS, and Lambda, and was validated through a three-way deployment process that ran both models in parallel to compare accuracy before fully transitioning.</p>

<h2>Maurycyz Demonstrates Method for Embedding Messages in RSA Public Keys</h2>
<a name="story-26975"><img src="https://wsrv.nl/?url=https%3A%2F%2Fmedia.cheggcdn.com%2Fmedia%2F953%2F953465fa-0f83-4ed1-80a1-e51a8e96df61%2FphpCpfLgU&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Maurycyz describes a method for embedding text messages within the modulus of RSA public keys used in SSL/TLS certificates. By modifying the bytes of a target modulus to include a message and then finding a nearby prime factor, a user can create a valid public key that can be signed by a Certificate Authority while concealing the hidden text in its base64-encoded representation.</p><p>The implementation involves finding a new prime factor that is close enough to the ideal quotient to maintain a valid modulus. Although this technique reduces the entropy of the private key, the author notes that the certificates remain secure for public web use due to the forward secrecy provided by modern TLS protocols.</p>

<h2>Julio Merino Launches ZKeys for Unattended Reboots of Encrypted Disks</h2>
<a name="story-26914"><img src="https://wsrv.nl/?url=https%3A%2F%2Fextradisks.com%2Fimages%2Fextradisksencrypteddisk.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Julio Merino has introduced ZKeys, a managed service designed to enable unattended, passwordless reboots for machines with encrypted disks without compromising data security. The service stores half of an encryption passphrase remotely while the other half remains on the client machine, requiring periodic keepalive pings over HTTPS to keep the volume unlocked.</p><p>If a client machine goes offline for an extended period—such as during a physical theft—the server automatically locks access to the key, preventing unauthorized data recovery. The open-source client currently includes integration support for FreeBSD and Fedora, relying on a split-key architecture and encryption at rest to protect against server compromises.</p>

<h2>Unconventional IPv4 Addressing and IDNA Mapping Quirks in getaddrinfo</h2>
<p>An analysis of glibc's getaddrinfo implementation demonstrates how combining the AI_IDN flag with UTS #46 Unicode mapping enables unorthodox characters—including mathematical alphabets, fullwidth digits, circled numbers, and invisible spaces—to translate into valid IPv4 addresses. Because Internationalized Domain Name conversion executes prior to the numeric address parser, various non-standard formats, mixed bases, and lookalike strings successfully resolve to standard IP destinations.</p><p>This behavior exposes vulnerabilities in security mechanisms such as SSRF filters, blocklists, and input validators that inspect raw strings instead of resolved endpoints. Attackers can exploit these parsing discrepancies and URL formatting conventions to disguise malicious destinations behind familiar domains or seemingly inert text, highlighting the importance of verifying fully resolved IP addresses rather than raw string inputs.</p>
