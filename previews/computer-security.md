<h2>Outlook.com Begins Rejecting Emails From Domains Without DMARC Records</h2>
<a name="story-26850"><img src="https://wsrv.nl/?url=https%3A%2F%2Fblog.mdaemon.com%2Fhs-fs%2Fhubfs%2FDMARC.png%3Fwidth%3D1280%26height%3D720%26name%3DDMARC.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Since early November 2026, Microsoft's consumer email services—including Outlook.com, Hotmail, Live, and MSN—have begun rejecting emails from domains that lack a published DMARC record. Unlike previous rules targeting high-volume bulk senders, this enforcement affects low-volume and individual senders, causing intermittent message bounces without public announcements from Microsoft.</p><p>Affected domains typically receive a "550 5.7.1 Message rejected" error even if SPF and DKIM are properly configured. Because Microsoft only rejects a portion of mail from non-compliant domains, the issue often goes unnoticed by senders. The problem can be resolved by publishing a basic DMARC TXT record with a policy set to none, provided that SPF or DKIM aligns with the sender's From address.</p>

<h2>Unconventional IPv4 Addressing and IDNA Mapping Quirks in getaddrinfo</h2>
<p>An analysis of glibc's getaddrinfo implementation demonstrates how combining the AI_IDN flag with UTS #46 Unicode mapping enables unorthodox characters—including mathematical alphabets, fullwidth digits, circled numbers, and invisible spaces—to translate into valid IPv4 addresses. Because Internationalized Domain Name conversion executes prior to the numeric address parser, various non-standard formats, mixed bases, and lookalike strings successfully resolve to standard IP destinations.</p><p>This behavior exposes vulnerabilities in security mechanisms such as SSRF filters, blocklists, and input validators that inspect raw strings instead of resolved endpoints. Attackers can exploit these parsing discrepancies and URL formatting conventions to disguise malicious destinations behind familiar domains or seemingly inert text, highlighting the importance of verifying fully resolved IP addresses rather than raw string inputs.</p>

<h2>PWN Research Details Firecracker MicroVM Escape and Host Root Execution</h2>
<a name="story-26759"><img src="https://wsrv.nl/?url=https%3A%2F%2Fpwn.ai%2Fapi%2Fblog%2Fimages%2Ffirecracker-host-integration-dbdde36ef234.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>PWN Research published a technical write-up detailing a complete escape from an AWS Firecracker microVM (version 1.16.1), demonstrating how a guest can achieve root code execution on the host.
