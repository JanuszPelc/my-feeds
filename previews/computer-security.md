<h2>Tech Startups and AI Labs Embrace Formal Verification to Secure Code</h2>
<a name="story-25911"><img src="https://wsrv.nl/?url=https%3A%2F%2Fbillionhopes.ai%2Fwp-content%2Fuploads%2F2026%2F02%2F5-KC-21-Billion-Hopes-Image-5-scaled.jpeg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Tech startups and major AI labs are increasingly turning to formal verification—a mathematical method used to prove code is bug-free—to secure software generated by artificial intelligence. <h2>TRM Labs Attributes Binance Crypto Theft to North Korea</h2>
<p>Blockchain analysis firm TRM Labs has attributed the theft of approximately $6.36 billion from Binance to TraderTraitor, a North Korea-based hacking group. <h2>David Buchanan Demonstrates C2PA Trust Model Vulnerabilities</h2>
<a name="story-25912"><img src="https://wsrv.nl/?url=https%3A%2F%2Fpub.mdpi-res.com%2Fapplsci%2Fapplsci-16-03391%2Farticle_deploy%2Fhtml%2Fimages%2Fapplsci-16-03391-g001.png%3F1775123784&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Security researcher David Buchanan has demonstrated a proof-of-concept showing how the Coalition for Content Provenance and Authenticity (C2PA) trust ecosystem could be compromised in a manner similar to the recent eMudhra certificate authority incident. <h2>Mark Blaszczyk Details Android SMS of Death Zero-Click Denial-of-Service Vulnerability</h2>
<a name="story-25838"><img src="https://wsrv.nl/?url=https%3A%2F%2Fblog.gridinsoft.com%2Fwp-content%2Fuploads%2F2025%2F01%2Fexploitation-process-samsung-zeroclick.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Security researcher Mark Blaszczyk has detailed a zero-click denial-of-service vulnerability in Android, dubbed "SMS of Death," which can crash the telephony service and drop active calls—including emergency calls—using a single malformed WAP Push message. The flaw stems from an unchecked cast of a WSP header length read as a 64-bit integer into a 32-bit signed integer, triggering a NegativeArraySizeException that terminates the telephony process without any user interaction or notification.</p><p>According to the disclosure, rapid transmission of the payload can corrupt the SQLite database behind SMS storage, causing persistent crash-on-boot loops that require removing the SIM card or using ADB for recovery. Despite being reported to the Android &amp; Google Devices VRP with a suggested one-line patch, Google ultimately classified the issue as a non-security issue and declined to fix it, prompting the researcher to publish a public proof-of-concept.</p>

<h2>V12 Research Reveals Weak AES-256 Key Generation in Multiple PDF Implementations</h2>
<a name="story-25784"><img src="https://wsrv.nl/?url=https%3A%2F%2Fv12.sh%2Fcdn%2F_astro%2Fcover.CF5x0X6B_1N5vR.webp&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Security researchers at V12 discovered that several popular PDF implementations generate AES-256 file keys from insufficiently random sources or excessively small state spaces, enabling attackers to decrypt protected documents without a password. In affected applications, the cryptographic keys are derived from predictable metrics rather than true random entropy.</p><p>Specifically, MuPDF's reliance on a linear congruential generator limits the effective entropy of its keys to just nine bits, making rapid brute-force recovery feasible within milliseconds. Similar predictable key derivation patterns were identified in Foxit and Java-based libraries like OpenPDF and iText, undermining the security guarantees of AES-256 encryption in previously generated files.</p>
<p><small>Links: <a href="https://v12.sh/blog/the-case-of-the-9bit-aes-key">v12.sh</a> | <a href="https://lobste.rs/s/dqexzg/case_9_bit_aes_key">discussion</a> | <a href="https://news.ycombinator.com/item?id=50280722">hacker news</a></small></p>
