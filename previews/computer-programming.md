<h2>Valkey 9.2 Replaces Skiplists with B+ Trees for Sorted Sets</h2>
<a name="story-28224"><img src="https://wsrv.nl/?url=https%3A%2F%2Fmedia.geeksforgeeks.org%2Fwp-content%2Fuploads%2F20240612133138%2Fb-plus-tree-in-c.webp&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Valkey 9.2 replaces its traditional skiplist implementation for large sorted sets with a high-fanout B+ tree variant named fbtree. This structural shift addresses the high memory overhead and cache-miss penalties inherent to skiplists by packing multiple elements into contiguous leaf nodes and utilizing SIMD-accelerated feature lookups.</p><p>Internal benchmarks show that fbtree reduces per-member memory overhead by 36 to 43 percent for large sorted sets while significantly improving throughput for update-heavy operations like ZADD and ZREM. While sorted set commands and behaviors remain functionally unchanged, the OBJECT ENCODING command now reports btree instead of skiplist.</p>

<h2>LookAtMyQuant Quantization Compiler Released on GitHub</h2>
<p>LookAtMyQuant is a quantization compiler that evaluates compression damage for individual model components to fit models within size budgets while minimizing Kullback-Leibler divergence. The MIT-licensed project provides an Apple Silicon MLX runtime alongside specialized compression recipes for large language models including Qwen and Inkling-2-Mini.</p><p>The compiler employs post-training quantization, trellis codes, row-specific bit allocation based on Fisher information, and multi-step distillation. Packed builds demonstrate strong benchmark performance and memory efficiency relative to standard alternatives, while the repository supplies command-line utilities and Python APIs for local deployment and evaluation.</p>

<h2>Oscar Molnar Analyzes Studio Display Ethernet Speed Bottleneck</h2>
<a name="story-28218"><img src="https://wsrv.nl/?url=https%3A%2F%2Fblog.tymscar.com%2Fstudio-display-ethernet%2Ffast-com.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Blogger Oscar Molnar discovered that routing a 2.5 Gbps internet connection through a USB-C Ethernet adapter plugged into an Apple Studio Display severely throttled download speeds to 600 Mbps, while upload speeds remained unaffected at 2.4 Gbps. Direct connection to his MacBook Pro yielded full speeds, pointing to a performance bottleneck introduced by the display's USB hub.</p><p>Further investigation revealed that the Realtek RTL8156B adapter dropped frames under high loads because its small USB burst size of four packets caused buffer overflows when combined with the hub's round-trip latency. Replacing it with a newer adapter using the RTL8157 chip, which supports an eight-packet burst size, eliminated the frame drops and restored full download performance without requiring network flow control.</p>

<h2>C Implementation of Android Binder Driver Removed from Linux Kernel</h2>
<a name="story-28141"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwww.diversifiedbinding.com%2Fcdn%2Fshop%2Ffiles%2Fdownload_4.png%3Fv%3D1762367146%26width%3D1946&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>At the Kangrejos 2026 conference, developers announced the complete removal of the C implementation of Android's Binder driver from the Linux kernel, finalized during the 7.4 merge window. The C version of Binder, which serves as the primary interprocess communication mechanism for Android, was heavily targeted by security vulnerabilities and accumulated significant technical debt over its eighteen-year history.</p><p>Replacing the driver with a Rust implementation took over five years, requiring careful debugging of tail latencies, lock contention, and tracepoint compatibility to prevent regressions across billions of devices. While vendor hooks and older stable kernel branches will continue to rely on the C version temporarily, maintainers emphasized that superseded C code should be deleted rather than maintained indefinitely on long-term support releases.</p>
