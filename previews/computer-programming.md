<h2>Keybytes Modular Keyboard Project Introduced</h2>
<p>Keybytes is an open-source, fully modular mechanical keyboard project where every individual key functions as its own rearrangeable 1u printed circuit board. Developed by NotARoomba, the system allows keys to be linked together in arbitrary configurations using magnetic cases and pogo pins on all four sides for power and I2C communication.</p><p>Each key module incorporates a CH32V003 RISC-V microcontroller to process inputs, while a central two-layer main board features an STM32WB55RGV6 microcontroller supporting Bluetooth and USB connectivity. The hardware also includes battery charging circuitry, a buck-boost converter, and 2MB of QSPI flash storage, with all design files, schematics, and CAD models published on GitHub.</p>

<h2>Arthur O’Dwyer Examines Fixits and Suppression Mechanisms in Compiler Warnings</h2>
<p>Arthur O’Dwyer explores two peripheral aspects of compiler diagnostic design: machine-readable fixits that prescribe treatments and suppression mechanisms used to silence warnings. He analyzes how compilers navigate the tension between changing code behavior to match likely programmer intent and preserving existing behavior.</p><p>O’Dwyer highlights that while some compilers offer both treatment and suppression options for ambiguous constructs, they often struggle with distinguishing typographical errors from deliberate code. He argues that diagnostic warning systems should employ relative rules evaluating the degree of syntactic ornamentation rather than absolute rules based on isolated patterns.</p>

<h2>OpenLDK: Java JIT Compiler and Runtime Written in Common Lisp</h2>
<p>OpenLDK is a just-in-time compiler and runtime for Java implemented entirely in Common Lisp, enabling Java libraries, classes, and multiple JVM languages to run natively within SBCL. By translating Java bytecode into Lisp code on demand, it bridges the two ecosystems so that Java classes map to CLOS classes, methods participate in CLOS method combinations, and applications share a single in-process heap.</p><p>The project supports a wide range of JVM-hosted languages like Kotlin, Scala, Groovy, and Clojure, allowing mixed-language expressions to be evaluated together. Additionally, by utilizing warm image saving features to preserve initialized object graphs, OpenLDK can boot complex frameworks like Spring Boot in approximately 84 milliseconds.</p>
<p><small>Links: <a href="https://atgreen.github.io/repl-yell/posts/openldk-java-in-common-lisp/">atgreen.github.io</a> | <a href="https://github.com/atgreen/openldk">source</a> | <a href="https://lobste.rs/s/cf8mdy/openldk_bringing_java_world_into_common">discussion</a></small></p>

<h2>DERIVE Automatically Reverse-Engineers Instruction Encodings</h2>
<p>DERIVE is a software tool that automatically extracts bit-level instruction encoding information by feeding permutations of assembly instructions into an assembler and analyzing the resulting machine code. Designed to eliminate the tedious and error-prone process of manually transcribing architecture reference manuals for binary tools like just-in-time compilers and disassemblers, DERIVE successfully solves instruction sets for major architectures including MIPS, SPARC, Alpha, and PowerPC.</p><p>Operating under the assumption that assembly transformations are stateless and field-independent, the tool utilizes specialized solvers for registers, immediates, and jump targets to generate C data structure declarations. The authors demonstrate DERIVE's practical utility by building a code emitter generator that automatically produces C macros, successfully reducing the backend description size of the Kaffe JIT compiler by 40 percent.</p>
<p><small>Links: <a href="https://www.usenix.org/legacy/events/usenix01/full_papers/hsieh/hsieh_html/">usenix.org</a> | <a href="https://lobste.rs/s/1q1rc1/reverse_engineering_instruction">discussion</a></small></p>
