<h2>Tabc Container Runtime Executes Docker Containers in Browser Tabs</h2>
<a name="story-28683"><img src="https://wsrv.nl/?url=https%3A%2F%2Ffzakaria.com%2Fassets%2Fimages%2Ftabc-demo.webp&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Tabc is an OCI-compliant container runtime that executes individual containers within separate browser tabs using a WebAssembly-compiled Linux kernel. Built on top of Pooya Parsa's unkernel project, the tool allows standard Docker and Docker Compose workflows to run directly in a browser without requiring a host Linux operating system or a dedicated virtual machine on macOS.</p><p>By leveraging Chromium's security sandbox, each container receives process and storage isolation without touching the host kernel, booting Alpine Linux images in under a second when reusing active browser sessions. While memory overhead is higher than native microVMs—costing roughly 540 megabytes of host memory per idle container—the approach eliminates the need for heavyweight Linux virtual machines on Apple Silicon and enables interactive terminal and web server integration directly through browser windows.</p>

<h2>Implementing Typed Indices in Zig</h2>
<p>The "Newtype Index" pattern in Zig prevents logic errors by ensuring that different arrays or slices cannot be accessed using the same index type. By utilizing `enum(u32)` to wrap integers, the compiler can catch instances where a developer accidentally swaps indices—for example, using a row index to access a column value in a spreadsheet—at compile time rather than at runtime.</p><p>The article demonstrates a practical "Struct of Arrays" example and offers a generic recipe using Zig's `comptime` functionality. This approach allows for a streamlined, automated way to define typed indices for multiple struct fields while providing a consistent accessor API. While the pattern is not perfectly hermetic due to the lack of private fields in Zig, it establishes a strong convention for safe data access.</p>

<h2>Armin Ronacher Proposes Abolishing Rust Mutex Poisoning</h2>

<p>Armin Ronacher argues that Rust's mutex poisoning should be removed or made an exception rather than the default behavior. While the feature was designed to signal broken invariants after a panic, the author asserts that it is rarely handled correctly in practice and often results in "slow outages" where a single panic on one thread makes a shared mutex permanently unusable for all subsequent threads.</p><p>The article highlights how `PoisonError` can cause deadlocks because it holds the lock, citing issues in projects like RLS and Mozilla, as well as crates like Deno and Polars. Ronacher suggests making `std::sync::nonpoison` the default for `std::sync::Mutex` and introducing an opt-in `Poison&lt;T&gt;` wrapper for users who specifically need to detect poisoned states.</p>
