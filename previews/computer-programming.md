<h2>EMACS Text Editor Turns 50</h2>
<a name="story-25734"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwp.technologyreview.com%2Fwp-content%2Fuploads%2F2026%2F09%2FScreenshot-2026-08-11-at-8.43.55-AM.jpg%3Fw%3D840&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Originally created at the MIT Artificial Intelligence Laboratory in 1976, the EMACS text editor is celebrating its 50th anniversary and remains widely used today. Developed initially as a set of macros for the TECO editor by researchers including Richard Stallman, Guy Steele Jr., and David Moon, EMACS provided a standardized, customizable full-screen editing experience that transformed how programmers interacted with computers.</p><p>The software-sharing culture surrounding early versions of EMACS directly influenced the emergence of the free software movement and the creation of the GNU Project. Over the decades, variants of the software were commercialized by companies like Honeywell and James Gosling, while others were integrated into operating systems such as Unix and early versions of Mac OS X, leaving a lasting legacy on modern software development environments.</p>
<p><small>Links: <a href="https://www.technologyreview.com/2026/10/20/1145399/emacs-turns-50/">technologyreview.com</a> | <a href="https://news.ycombinator.com/item?id=50273171">hacker news</a></small></p>

<h2>Daniel Lemire Details Billion-Query-Per-Second Lookup Tables in C++</h2>
<a name="story-25731"><img src="https://wsrv.nl/?url=https%3A%2F%2Flemire.me%2Fblog%2Fwp-content%2Fuploads%2F2026%2F10%2Fperfect-hash-http-headers.webp&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Daniel Lemire and Francisco Geiman Thiesen have released a C++23 library that implements compile-time perfect hashing to map static strings to values at speeds exceeding one billion lookups per second. By generating a collision-free hash function during compilation, the approach eliminates runtime collision resolution and hashing overhead.</p><p>The technique relies on association tables and key lengths to compute slot indices with minimal bitwise operations, while utilizing 16-byte vector registers and zero-padding to accelerate string comparisons. Benchmarks demonstrate that the method completes lookups in roughly five CPU cycles, significantly outperforming traditional containers like std::unordered_map as well as the GNU gperf tool.</p>
<p><small>Links: <a href="https://lemire.me/blog/2026/10/26/billion-query-per-second-lookup-tables-in-c/">lemire.me</a> | <a href="https://lobste.rs/s/d3ubhd/billion_query_per_second_lookup_tables_c">discussion</a> | <a href="https://news.ycombinator.com/item?id=50271088">hacker news</a></small></p>

<h2>Haskell-Like Type Class Resolution Implemented in Pure Java</h2>
<a name="story-25714"><img src="https://wsrv.nl/?url=https%3A%2F%2Fimage3.slideserve.com%2F5573386%2Ftype-classes-l.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>A software engineering blog post explores how Java's existing type system can support Haskell-style type class instance resolution entirely in plain Java without language modifications. By combining runtime reflection, generic type metadata, and a compact type unification engine, the approach automatically resolves both first-order and higher-kinded type classes while supporting overlapping instances and nested generic types.</p><p>Although presented as an experimental exploration rather than a production library, the project demonstrates the surprising amount of structure Java preserves at runtime for advanced type-level programming. A complete reference implementation is publicly available via GitHub and a GitHub Gist for developers examining metaprogramming techniques in Java.</p>

<h2>AlpineBSD Operating System Combines NetBSD Kernel with Alpine Linux-Inspired Userspace</h2>
<a name="story-25677"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwww.netbsd.org%2Fdocs%2Fpuffs%2Frump.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>AlpineBSD is a work-in-progress operating system that pairs the NetBSD kernel, libc, and essential platform-specific tools with a userspace inspired by Alpine Linux. The project aims to minimize the inclusion of AI-generated software, excluding large language model output entirely from its base system and main package repository.</p><p>While it utilizes the apk-tools package manager and BusyBox like Alpine Linux, AlpineBSD features a slightly more GNU-oriented userspace and currently relies on the s6 init system, with plans to add OpenRC support. Because it is built on the NetBSD kernel, the operating system currently lacks an official installer and has limited hardware support compared to Linux distributions.</p>

<h2>Lexifina Proposes Git-Style Version Control for US Code</h2>
<p>Legal technology company Lexifina has developed a version-control system for the United States Code, allowing users to track legislative amendments in a manner similar to software source code management. By replaying historical amendments sequentially across nine code titles from 2017 onward, the project successfully reproduced 361 out of 365 changes to match official release points.</p><p>The system aims to address challenges in legal research and language model accuracy, which often falter when handling temporal validity and statutory evolution. While the tool successfully maps effective dates and amending laws for most changes, limitations remain regarding retroactive reach-back provisions and pattern-matching constraints for effective-date notes.</p>

<h2>Call Graph Analyzer Released for Rust Panic Detection</h2>
<a name="story-25655"><img src="https://wsrv.nl/?url=https%3A%2F%2Fdoc.castsoftware.com%2Finterface%2Fanalysis-config%2Ftransactions%2Ftransactions%2Fcall-graph%2Fcall_graph.jpg&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Developed by the Open Device Partnership and Microsoft, the Call Graph Analyzer (CGA) extracts callgraphs from monomorphized Mid-level Intermediate Representation (MIR) to identify potential panic paths in Rust binaries. This MIR-based approach allows the tool to detect panics originating within dependencies and the standard library, providing more comprehensive coverage than HIR-based or linker-based methods.</p><p>CGA operates as a rustc-driver, meaning it requires a specific nightly version of the Rust compiler and must be installed directly from its source repository rather than crates.io. The tool is specifically designed to assist developers of embedded and mission-critical systems in minimizing unrecoverable error conditions and reasoning about panic paths.</p>
<p><small>Links: <a href="https://tweedegolf.nl/en/blog/242/finding-panics-with-call-graph-analyzer/">tweedegolf.nl</a> | <a href="https://github.com/opendevicepartnership/cga">source</a> | <a href="https://lobste.rs/s/opqtiv/finding_panics_with_call_graph_analyzer">discussion</a></small></p>

<h2>Discord to Enable Web Search for Discoverable Server Content</h2>
<a name="story-25648"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwww.computerhope.com%2Fissues%2Fpictures%2Fdiscord-public-server-requirements.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Discord is introducing features to make content from its Discoverable Servers more searchable on the web. Starting November 16, 2026, all Discoverable Servers will feature web pages that may include automated Channel Summaries of active conversations. By mid-December 2026, messages from public channels may also appear in web search results to help users find specific information.</p><p>Admins can manage channel visibility through "Web Presence" settings, and users can opt out of message sharing via their privacy settings. These updates are limited to Discoverable Servers and do not affect private servers, direct messages, or group DMs. In regions such as the EU and UK, the message-sharing feature will be disabled by default.</p>

<h2>Amazon Discourages &quot;Tokenmaxxing&quot; in Software Engineering AI Guidelines</h2>
<a name="story-25608"><img src="https://wsrv.nl/?url=https%3A%2F%2Fmedia.licdn.com%2Fdms%2Fimage%2Fv2%2FD5612AQFCSABuNVOOXw%2Farticle-cover_image-shrink_720_1280%2FB56Z6M5V4THcAU-%2F0%2F1780480306449%3Fe%3D2147483647%26v%3Dbeta%26t%3D1dB3PuExKpaFNheZVQh3z1Mhfq3Qv9Ax2fdVBlTJevQ&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Amazon has issued new AI usage guidelines to its software development engineers and managers, advising against "tokenmaxxing"—the practice of using AI tools excessively without regard for actual output quality. The company's memo describes metrics like token usage and tool adoption rates as "deeply flawed" ways to measure productivity, suggesting instead that focus should be placed on long-term outcomes and "feature velocity," such as successful production launches.</p><p>The guidance follows Amazon's decision in May to shut down an internal AI leaderboard that employees used to climb rankings through high token consumption. As businesses manage the rising costs of AI processing, Amazon's policy aims to prevent wasted computational effort on tasks that do not require AI. The company also noted that an engineer's ability to identify when AI is not useful for a task is a demonstration of high-quality professional judgment.</p>
<p><small>Links: <a href="https://www.cnbc.com/2026/10/27/amazon-ai-coding-tokenmaxxing.html">cnbc.com</a> | <a href="https://www.aboutamazon.com/news/company-news/amazon-software-engineer-role-guideline-ai">source</a> | <a href="https://news.ycombinator.com/item?id=50268075">hacker news</a></small></p>
