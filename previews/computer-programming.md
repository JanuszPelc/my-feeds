<h2>Tangled Releases Federated Code Forge Built on AT Protocol</h2>
<a name="story-25981"><img src="https://wsrv.nl/?url=https%3A%2F%2Fassets.tangled.network%2Fblog%2Fforge%2Fog.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Tangled has introduced a federated code forge built on the AT Protocol, enabling users to self-host components such as Git hosting, CI runners, or entire API servers while collaborating seamlessly across independent instances. <h2>Shane Friedman Examines Npm Package Name Similarity Rules</h2>
<a name="story-25979"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwww.microsoft.com%2Fen-us%2Fsecurity%2Fblog%2Fwp-content%2Fuploads%2F2026%2F05%2Fimage-172.webp&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Developer Shane Friedman details his experience attempting to publish an npm package named "estee" as a short nickname for an audiobook alignment tool, only to be blocked by the registry's automated similarity checks. The system flagged the name as too similar to existing packages like "testem" and "espree" based on a Levenshtein distance threshold.</p><p>The author analyzes the mathematical scaling issues of applying a flat Levenshtein distance threshold to short string lengths, which drastically restricts available namespaces and flags unrelated names such as "hoid." Although npm support confirmed that automated typosquatting blocks cannot be bypassed, the incident highlights the ongoing challenge of balancing security against malicious squatting with accommodating legitimate short package names.</p>

<h2>Curl Accidentally Turing-Complete for Nine Months</h2>
<a name="story-25923"><img src="https://wsrv.nl/?url=https%3A%2F%2Fseriot.ch%2Fresources%2Fcurl_config.png&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
<p>Between versions 8.12 and 8.16, the command-line data transfer tool curl possessed features that made it accidentally Turing-complete under unbounded resource assumptions. Config files could slice variable values and recursively include other files without an explicit depth cap, enabling the utility to simulate any two-counter Minsky program.</p><p>Release 8.17.0 introduced a five-level include cap that broke this reduction by restricting file inclusion depth. Although real-world physical constraints such as stack limits and memory allocation restricted execution depth in practice, the behavior illustrated how unexpected computational capabilities can emerge from configuration parsers.</p>

<h2>Overview of PDP Computers History and Evolution</h2>

<p>An overview examines the history, speed, pricing, and architectural evolution of Digital Equipment Corporation's PDP computers from the introduction of the PDP-1 through the VAX series. <h2>H.264 Video Compression Explained</h2>
<a name="story-25885"><img src="https://wsrv.nl/?url=https%3A%2F%2Fwww.ampltd.com%2Fwp-content%2Fuploads%2F2017%2F06%2Fh264hd2000-function-diagram.gif&amp;w=1200&amp;h=1200&amp;fit=inside&amp;we&amp;output=jpg&amp;bg=white" width="30%" align="right" /></a>
